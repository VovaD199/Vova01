# Підсумок перевірки гіпотез (пісочниця, 12 листопада 2026)

Короткий звіт про експерименти на навчальній копії сайту Фундації Лятошинського. Застосунок працює локально; база даних для демо створюється в пам’яті при запуску й наповнюється стартовими даними з файлу seed.

## 1. Гіпотеза: які питання ми тестували

Ми перевіряли три незалежні ідеї в одній пісочниці:

1. **Звернення в контактній формі.** Чи зручніше користувачам дозволити коротші повідомлення (мінімум 5 символів замість 10) на сторінці контактів і в пов’язаних формах?
2. **Сторінка «Про нас».** Як виглядає сторінка, якщо прибрати з демо-контенту блок «Наша місія»?
3. **Сторінка «Підтримати».** Чи краще для стейкхолдерів звучить заклик «Стати меценатом» (англійською «Become a patron») на головній кнопці форми швидкого донату, ніж попередній текст про внесок?

## 2. Налаштування пісочниці

- **Гілка:** `poc/day-3`.
- **Контроль даних:** зміни внесено у файл початкового наповнення бази `scripts/seed-memory-mongo.js`. При кожному `npm run dev` демо-база знову створюється в пам’яті й завантажує оновлений вміст. Після зупинки сервера дані зникають — це не зміна бойового сайту.
- **Тексти на екрані:** окремо змінено файли перекладів `i18n/messages/uk.json` та `en.json` для повідомлень про помилки в формі й підпису кнопки донату.

## 3. Зроблені зміни (простими словами)

1. Дозволили надсилати в зверненні текст від п’яти символів — і на екрані форми, і при перевірці на сервері; оновили тексти помилок українською та англійською.
2. Прибрали з демо-сторінки «Про нас» блок «Наша місія» (заголовок, тексти, зображення в демо-наповненні).
3. Змінили підпис кнопки в блоці швидкого донату на сторінці підтримки на «Стати меценатом» / «Become a patron»; кнопка в футері сайту не змінювалась.
4. Підлаштували автоматичні перевірки в коді під нові правила довжини повідомлення та новий підпис кнопки.

## 4. Докази

**Поведінка та спостереження в браузері**

У межах цієї сесії **не зафіксовано** обов’язкової перевірки всіх трьох змін у запущеному застосунку з боку аналітика (скріншотів у чаті немає). Рекомендовані точки перевірки для наступного огляду:

- `/uk/contacts` або `/en/contacts` — коротке повідомлення (5–9 символів) і текст помилки при менше ніж 5.
- `/uk/about-us` після перезапуску `npm run dev` — чи немає секції «Наша місія», чи відкривається сторінка без помилки.
- `/uk/support-us` та `/en/support-us` у режимі розробки (не заглушка «в розробці») — новий підпис на кнопці донату.

**Технічні докази з сесії**

- Автоматичні тести перевірки контактної форми та серверної логіки довжини повідомлення пройшли після зміни порогу на 5 символів.
- Обсяг змін у гілці (команда `git diff --stat`): **8 файлів**, **10 рядків додано**, **19 видалено**, зокрема 9 рядків видалено лише в seed для блоку «Місія».

## 5. Чекліст валідації

### Зміна 1: коротші повідомлення в контактній формі (мінімум 5 символів)

| | |
|---|---|
| **Доведено** | У коді оновлено форму, серверне правило та тексти помилок; автоматичні тести для цієї логіки пройшли. |
| **Не доведено** | Повний шлях користувача в браузері (ввід → відправка → відповідь сервера) для 5 символів на обох мовах; однаковість поведінки в усіх місцях, де та сама форма (контакти, співпраця, модальні вікна). |
| **Потрібен розробник** | Чи прийнятне для Фундації офіційне зменшення мінімуму (спам, якість звернень); чи узгодити обрізання пробілів на сервері так само, як у формі; оновлення правил у документації, якщо зміну переносять у продукт. |

### Зміна 2: прибраний блок «Наша місія» в демо «Про нас»

| | |
|---|---|
| **Доведено** | У файлі seed для демо прибрано вміст блоку «Наша місія». |
| **Не доведено** | Чи сторінка «Про нас» стабільно відкривається після перезапуску (у продуктовій схемі блок місії може бути обов’язковим). |
| **Потрібен розробник** | Чи це навмисне продуктове рішення, чи лише експеримент у демо-даних; чи треба змінювати схему сторінки, якщо місію прибирають назавжди. |

### Зміна 3: підпис «Стати меценатом» на кнопці донату

| | |
|---|---|
| **Доведено** | Тексти кнопки оновлено в перекладах для форми на сторінці підтримки; тести форми підлаштовано під новий український підпис. |
| **Не доведено** | Вподобання стейкхолдерів після перегляду на uk/en; чи не плутають користувачі цю кнопку з іншою кнопкою підтримки у футері. |
| **Потрібен розробник** | Чи формулювання «меценат» відповідає юридичній та фінансовій моделі; чи узгоджувати інші заклики на сайті; доступ до сторінки підтримки на бойовому середовищі (заглушка «в розробці»). |

## 6. Рекомендований наступний крок

Розділити три гіпотези на окремі рішення продукту, провести короткий огляд у браузері за чеклістом вище й винести на розробника лише ті зміни, які стейкхолдери схвалюють для переносу з пісочниці.
